# Deployment Guide — LCMS

## Overview

LCMS is deployed using:
- **Vercel** for the Next.js application
- **Supabase** (hosted) for database, auth, and storage
- **GitHub** as the source of truth and CI/CD trigger

---

## Environments

| Environment | Branch | URL |
|-------------|--------|-----|
| Development | local | http://localhost:3000 |
| Preview | develop | Auto-generated by Vercel |
| Production | main | https://your-domain.com |

---

## Step 1 — Create Production Supabase Project

Create a **separate** Supabase project for production:

1. Go to https://supabase.com
2. Create a new project named `lcms-prod`
3. Apply all migrations the same way as development
4. Configure Auth, Storage buckets, and Redirect URLs with your production domain

> Never use your development Supabase project in production.

---

## Step 2 — Push Code to GitHub

```bash
git add .
git commit -m "feat: initial project setup"
git push origin main
```

---

## Step 3 — Connect to Vercel

1. Go to https://vercel.com and log in
2. Click **Add New → Project**
3. Import your GitHub repository
4. Vercel will auto-detect Next.js — no build settings needed

---

## Step 4 — Configure Environment Variables in Vercel

In Vercel project dashboard → **Settings → Environment Variables**, add:

| Variable | Environment |
|----------|-------------|
| `NEXT_PUBLIC_SUPABASE_URL` | Production, Preview |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Production, Preview |
| `SUPABASE_SERVICE_ROLE_KEY` | Production, Preview |

Use **production** Supabase values for the Production environment.
Use **development** Supabase values for the Preview environment.

---

## Step 5 — Deploy

Vercel deploys automatically on every push:

- Push to `main` → deploys to production
- Push to `develop` → creates a preview deployment with a unique URL

Manual deploy:
```bash
vercel --prod
```

---

## Step 6 — Configure Custom Domain (Optional)

1. In Vercel → **Settings → Domains**
2. Add your domain
3. Follow DNS configuration instructions
4. Update Supabase Auth **Site URL** and **Redirect URLs** to use your domain

---

## Deployment Checklist

Before going live, confirm:

- [ ] All environment variables set in Vercel
- [ ] Production Supabase project has all migrations applied
- [ ] Supabase Auth redirect URLs include production domain
- [ ] Storage buckets created in production Supabase
- [ ] First super admin created in production
- [ ] All public pages load correctly
- [ ] Auth flow (register, verify, login) works in production
- [ ] File uploads work in production
- [ ] Custom domain configured and HTTPS active
- [ ] Lighthouse performance score > 85

## Branch Strategy

```
main          Production — protected branch, requires pull request
  ↑
develop       Integration — all features merge here first
  ↑
feature/*     Individual features (e.g. feature/member-portal)
fix/*         Bug fixes (e.g. fix/rls-events-policy)
```

### Commit Message Convention

Follow Conventional Commits: https://www.conventionalcommits.org

```
feat: add member profile page
fix: correct RLS policy on events table
docs: update setup guide
chore: upgrade dependencies
refactor: extract StatsCard component
style: fix mobile nav spacing
```

---

## Rollback

To roll back a production deployment:

1. Go to Vercel → **Deployments**
2. Find the last working deployment
3. Click the three-dot menu → **Promote to Production**

---

## Monitoring

- **Vercel Analytics** — page views, performance
- **Supabase Dashboard** — database queries, auth events, storage usage
- Check Vercel **Function Logs** for server-side errors
